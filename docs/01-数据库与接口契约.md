# IF-OA 数据库与接口契约 v0.4

> v0.4：补 3 个缺口端点：GET /users/{id}/avatar（头像图）、GET /approvals/{id}（审批详情）、GET /admin/users（用户管理列表）。
> v0.3：群公共区写权限放宽为全体群成员。v0.2：files 增加 group_id（群公共文件区，详见 docs/02 灵动岛设计）。
> 客户端（WinUI3/C++）与服务端（FastAPI/Python）的唯一契约。
> 改动本文档必须双方同步确认。
> 约定：时间一律 TEXT ISO8601 UTC；id 一律 INTEGER 自增主键；金额/数量不做特殊处理。

## 一、数据库表（SQLite）

### 1. 组织与用户

```sql
CREATE TABLE departments (
  id         INTEGER PRIMARY KEY,
  name       TEXT NOT NULL,
  parent_id  INTEGER REFERENCES departments(id),  -- NULL=顶级
  leader_id  INTEGER                              -- 部门领导，审批流用
);

CREATE TABLE users (
  id            INTEGER PRIMARY KEY,
  username      TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,
  display_name  TEXT NOT NULL,
  department_id INTEGER REFERENCES departments(id),
  role          TEXT NOT NULL DEFAULT 'member',   -- 'admin' | 'member'
  avatar_path   TEXT,                             -- 服务器磁盘路径，可空
  status        TEXT NOT NULL DEFAULT 'active',   -- 'active' | 'disabled'
  created_at    TEXT NOT NULL
);
```

### 2. 文件（公共/个人/聊天图片，一张表）

```sql
CREATE TABLE files (
  id          INTEGER PRIMARY KEY,
  scope       TEXT NOT NULL,        -- 'public' | 'personal' | 'chat'
  group_id    INTEGER REFERENCES conversations(id), -- 仅 scope=public：NULL=全员公共区，非空=该群公共区
  owner_id    INTEGER REFERENCES users(id),  -- public 时=上传者; personal/chat 时=属主
  folder      TEXT NOT NULL DEFAULT '',      -- 虚拟目录，'' 为根目录
  name        TEXT NOT NULL,                 -- 原文件名
  disk_path   TEXT NOT NULL,                 -- 服务器磁盘路径
  size        INTEGER NOT NULL,
  mime        TEXT NOT NULL,
  created_at  TEXT NOT NULL,
  deleted_at  TEXT                           -- 软删除（回收站 P1）
);
CREATE INDEX idx_files_scope ON files(scope, owner_id, folder);

CREATE TABLE favorites (                -- "喜欢的照片" = 对 personal 图片文件的收藏
  user_id INTEGER NOT NULL REFERENCES users(id),
  file_id INTEGER NOT NULL REFERENCES files(id),
  PRIMARY KEY (user_id, file_id)
);
```

权限：`public` 且 group_id 为空——全员读、admin 写；`public` 且 group_id 非空（群公共区）——**群成员读写**（非成员不可见）；`personal` 仅 owner；`chat` 仅会话成员（通过消息间接访问）。

### 3. 聊天（单聊/群聊统一会话模型）

```sql
CREATE TABLE conversations (
  id         INTEGER PRIMARY KEY,
  type       TEXT NOT NULL,            -- 'single' | 'group'
  name       TEXT,                     -- 仅群聊
  owner_id   INTEGER REFERENCES users(id),  -- 群主
  created_at TEXT NOT NULL
);

CREATE TABLE conversation_members (
  conversation_id     INTEGER NOT NULL REFERENCES conversations(id),
  user_id             INTEGER NOT NULL REFERENCES users(id),
  last_read_message_id INTEGER NOT NULL DEFAULT 0,   -- 未读数 = 大于此的条数
  PRIMARY KEY (conversation_id, user_id)
);

CREATE TABLE messages (
  id              INTEGER PRIMARY KEY,
  conversation_id INTEGER NOT NULL REFERENCES conversations(id),
  sender_id       INTEGER NOT NULL REFERENCES users(id),
  type            TEXT NOT NULL,      -- 'text' | 'image' | 'file'
  content         TEXT NOT NULL,      -- text=正文; image/file=files.id 字符串
  created_at      TEXT NOT NULL
);
CREATE INDEX idx_messages_conv ON messages(conversation_id, id);
```

单聊约定：首次发消息时 find-or-create 一个 `type='single'`、恰好 2 个成员的会话，客户端无需先建会话。

### 4. 审批流（顺序链：节点 1→2→…→n 逐级审批）

```sql
CREATE TABLE approval_templates (
  id          INTEGER PRIMARY KEY,
  name        TEXT NOT NULL,          -- 请假 / 报销 / ...
  form_schema TEXT NOT NULL,          -- JSON: 字段定义数组
  created_by  INTEGER REFERENCES users(id),
  created_at  TEXT NOT NULL
);
-- form_schema 示例:
-- [{"key":"days","label":"天数","type":"number","required":true},
--  {"key":"reason","label":"事由","type":"text","required":true}]

CREATE TABLE approval_nodes (
  id            INTEGER PRIMARY KEY,
  template_id   INTEGER NOT NULL REFERENCES approval_templates(id),
  seq           INTEGER NOT NULL,           -- 1 起的顺序
  name          TEXT NOT NULL,              -- "组长审批"
  approver_type TEXT NOT NULL,              -- 'fixed_user' | 'dept_leader'
  approver_id   INTEGER REFERENCES users(id) -- fixed_user 时必填
);

CREATE TABLE approvals (
  id           INTEGER PRIMARY KEY,
  template_id  INTEGER NOT NULL REFERENCES approval_templates(id),
  applicant_id INTEGER NOT NULL REFERENCES users(id),
  title        TEXT NOT NULL,
  form_data    TEXT NOT NULL,         -- JSON: 按 form_schema 填写的值
  status       TEXT NOT NULL,         -- 'pending' | 'approved' | 'rejected' | 'cancelled'
  current_seq  INTEGER NOT NULL DEFAULT 1,
  created_at   TEXT NOT NULL,
  finished_at  TEXT
);

CREATE TABLE approval_records (        -- 每次审批动作留痕
  id          INTEGER PRIMARY KEY,
  approval_id INTEGER NOT NULL REFERENCES approvals(id),
  node_seq    INTEGER NOT NULL,
  approver_id INTEGER NOT NULL REFERENCES users(id),
  action      TEXT NOT NULL,          -- 'approved' | 'rejected'
  comment     TEXT,
  created_at  TEXT NOT NULL
);
```

"待我审批"查询：`approvals.status='pending'` 且当前节点(seq=current_seq)的审批人 = 我
（`dept_leader` 类型运行时解析为申请人所在部门的 leader_id）。

### 5. 待办与通知

```sql
CREATE TABLE todos (
  id         INTEGER PRIMARY KEY,
  user_id    INTEGER NOT NULL REFERENCES users(id),
  content    TEXT NOT NULL,
  done       INTEGER NOT NULL DEFAULT 0,
  due_at     TEXT,                     -- 可空
  created_at TEXT NOT NULL
);

CREATE TABLE notifications (
  id         INTEGER PRIMARY KEY,
  user_id    INTEGER NOT NULL REFERENCES users(id),
  type       TEXT NOT NULL,            -- 'approval' | 'chat' | 'system'
  payload    TEXT NOT NULL,            -- JSON，结构随 type
  is_read    INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL
);
```

## 二、REST 接口（前缀 /api，认证方式：Header `Authorization: Bearer <jwt>`）

统一错误：非 2xx 返回 `{"detail": "原因"}`。JWT 有效期 7 天，过期重新登录（v1 不做 refresh token）。

### 认证与个人信息

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | /auth/login | `{username,password}` → `{token, user}` |
| GET | /users/me | 当前用户信息 |
| PUT | /users/me | 改 display_name / avatar（multipart） |
| PUT | /users/me/password | `{old_password,new_password}` |
| GET | /users/{id}/avatar | 头像图片（FileResponse，登录即可访问） |

### 组织架构

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /departments | 部门树 + 每部门成员（选人、通讯录共用） |
| POST/PUT/DELETE | /admin/departments | admin |
| GET | /admin/users | admin，用户管理列表 |
| POST/PUT/DELETE | /admin/users | admin，含重置密码/停用 |

### 文件

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /files?scope=&folder=&group_id= | 列表（scope=public 时 group_id 空=全员区、非空=群区；personal 自动取当前用户） |
| POST | /files/upload | multipart：file, scope, folder, group_id（全员区需 admin，群区群成员可写） |
| GET | /files/{id}/download | 校验权限后 FileResponse |
| DELETE | /files/{id} | owner 或 admin，软删除 |
| POST / DELETE | /files/{id}/favorite | 收藏/取消 |
| GET | /favorites | 收藏列表（照片墙数据源，按 mime=image 过滤） |

### 聊天

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /conversations | 会话列表（含最后一条消息、未读数、对方/群信息） |
| POST | /conversations | 建群 `{name, member_ids}` |
| POST | /conversations/{id}/members | 加人（群主） |
| GET | /conversations/{id}/messages?before_id=&limit=50 | 向上翻页 |
| POST | /conversations/{id}/messages | `{type,content}`；单聊用 `POST /conversations/single/{peer_user_id}/messages` 自动建会话 |
| PUT | /conversations/{id}/read | 标记已读（body 可空，服务端取最新消息 id） |

### 审批

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /approval/templates | 模板列表（发起页用） |
| POST | /approvals | `{template_id, title, form_data}` → 自动路由到节点1 |
| GET | /approvals?box=todo\|done\|sent | 待我审批 / 我已审批 / 我发起的 |
| GET | /approvals/{id} | 详情：表单数据+审批链+留痕（申请人/参与审批者可见） |
| POST | /approvals/{id}/action | `{action:'approve'\|'reject', comment}` 仅当前节点审批人 |
| POST | /approvals/{id}/cancel | 仅申请人，且 status=pending |
| POST/PUT/DELETE | /admin/approval/templates | admin，nodes 随 body 内嵌提交 |

### 待办

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET / POST | /todos | 列表 / 新建 `{content,due_at?}` |
| PUT / DELETE | /todos/{id} | 改（done/content/due_at）/ 删 |

### 通知

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /notifications?unread=1 | 列表（胶囊角标数据源） |
| PUT | /notifications/read | `{ids:[...]}` 标记已读 |

### 天气

不走后端：客户端直连 `https://api.open-meteo.com`（免费无 key）。

## 三、WebSocket（`/ws?token=<jwt>`）

服务端 → 客户端推送（JSON）：

```json
{"type": "message.new",       "data": {"conversation_id":1, "message": {...}}}
{"type": "approval.update",   "data": {"approval_id":3, "status":"pending", "actor":"张三"}}
{"type": "notification.new",  "data": {"unread_total": 5, "notification": {...}}}
```

客户端 → 服务端：仅 `{"type":"ping"}`（30s 一次心跳，60s 无消息判掉线重连）。

所有写操作走 REST，WS 只做推送 —— 客户端逻辑简单，服务端不用处理 WS 上的业务。

## 四、已知的刻意取舍（ponytail 标记）

1. **审批只做顺序链**，无会签/并行/条件分支。升级路径：approval_nodes 加 `branch_expr` 列。
2. **不做 refresh token**，7 天过期重登。用户抱怨后加。
3. **聊天无已读回执/撤回**，只有未读数。消息表加字段即可扩展。
4. **文件不分片上传**，单请求上限 200MB（uvicorn 层限制）。
5. departments.leader_id 换人时，进行中的 dept_leader 审批按新 leader 走。
